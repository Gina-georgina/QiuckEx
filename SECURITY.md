# Security Policy

## Supported Versions

The following versions of QuickEx are currently supported with security updates:

| Version | Supported |
| ------- | --------- |
| main (latest) | ✅ Yes |
| develop | ✅ Yes |
| < latest release | ⚠️ Best effort |

## Reporting a Vulnerability

If you believe you have found a security vulnerability in QuickEx, we appreciate your help in disclosing it responsibly. Please do **not** open a public GitHub issue.

### Preferred Reporting Channels

- **GitHub Security Advisories (Recommended)**: [Report a vulnerability](https://github.com/Viky207/QiuckEx/security/advisories/new) via GitHub's private vulnerability reporting.
- **Email**: Send details to [security@quickex.to](mailto:security@quickex.to). If possible, encrypt your message using our PGP key (available on request).

### What to Include

To help us triage and fix the issue quickly, please include:

- A description of the vulnerability and its potential impact
- Steps to reproduce (proof of concept, scripts, or screenshots)
- Affected components (frontend, backend, smart contracts, mobile, etc.)
- Suggested fix or mitigation if available
- Your contact information for follow-up

## Response SLA

| Severity | Acknowledgment | Target Fix | Disclosure |
| -------- | ------------- | ---------- | ---------- |
| Critical | Within 48 hours | Within 14 days | Coordinated after fix is deployed |
| High | Within 48 hours | Within 21 days | Coordinated after fix is deployed |
| Medium | Within 48 hours | Within 30 days | Coordinated after fix is deployed |
| Low | Within 72 hours | Best effort | Coordinated as appropriate |

## Responsible Disclosure Policy

We ask that you:

- Give us reasonable time to investigate and remediate the issue before public disclosure
- Avoid accessing, modifying, or deleting data that doesn't belong to you
- Do not perform denial-of-service attacks or degrade the service
- Act in good faith to avoid privacy violations and disruption to users

## CVE/GHSA Process

- We will coordinate with you on the timing of disclosure
- For qualifying vulnerabilities, we will request a CVE through GitHub Security Advisories or MITRE
- We will credit reporters in the security advisory unless you prefer to remain anonymous
- Once a fix is released, we will publish a GitHub Security Advisory (GHSA) with details and remediation guidance

## Security Best Practices for Users

- Always verify payment links before sending funds
- Use official QuickEx domains only
- Keep your Stellar wallet software up to date
- Enable hardware wallet signing when available
- Report suspicious links using the in-app scam alert features

Thank you for helping keep QuickEx and its users safe!
